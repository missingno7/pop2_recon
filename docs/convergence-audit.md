## What transfers from SimAnt

**Declaration context is a demonstrated new lead.** SimAnt's
`evidence/codegen/SYM-1-declaration-position.json` compares one independent source
with an unused declaration before or after its referenced extern declarations.
Fresh compilation here under pinned MSC 6.00 and
`/c /AM /Oe /Gs /Zl /Gc` emits 126 bytes for the baseline, 130 for the preceding
declaration and 126 for the following declaration. Under `/Oeg` the sizes are
152, 150 and 152. Each following-declaration control has the baseline's complete
raw CODE hash. The changed code includes arithmetic operand/load order.

These probes use explicit far globals and an explicit far pointer. They establish
context sensitivity under our compiler flags, not its cause or applicability to
the near-data signed-value target. Raw fixups and secondary CONST storage remain
unbound and unowned; equal CODE hashes do not mean equal bindings. The unused
declaration is a diagnostic contrast, not an original-source proposal. Recover
real declarations, types, parameter spelling and preceding definitions from
independent evidence before any canonical source change. SimAnt's REG-2/REG-3
return-local/reference-weight experiments are additional leads requiring local
controls; arbitrary unused-identifier padding is not a reconstruction strategy.

**The working AX runner is available locally, but did not solve membership.**
SimAnt pins `C:/tools/msc-6.00ax-archive`, runs `CL /EM` under headless DOSBox-X
with XMS, and mounts its compiler tree read-only. After verifying all eight
compiler-file hashes and the runner hash, this audit reproduced the accepted
42-byte `IS_FOUR_KIND` control and the stalled membership source. Both complete
objects are identical to their MSC 6.00 counterparts. Membership remains 78
bytes, first difference 73, against the complete 80-byte original target.
The old `msc600ax_local` failure therefore does not show that AX is unavailable;
it describes that runner/pass invocation. No existing lock or profile was changed.

**Whole-file context and relocation order are useful research evidence.**
SimAnt's `docs/tu-evidence.md` and `docs/codegen-rules.md` preserve source order,
declarations, peer functions and OMF record breaks. Adopt that discipline when
forming a TU hypothesis here. Our medium-model matches and overlapping overlay
spaces do not inherit SimAnt's large-model frame-to-TU mapping. Research may
compile a multi-function object, but the current pop2 acceptance gate still
requires one public owning one complete CODE segment. Grouped-TU promotion would
need a separately justified gate, not slicing peers away. `/Zi`/`/Zd` order
effects are a later controlled probe; debug storage is currently unsupported.

**A blocker dependency view reduces repeated work.** SimAnt's generated status
and `evidence/canonical/blockers.json` separate prerequisite evidence from the
dependent claims. Here the wave receipts already contain good resume conditions;
assemble them into each supervisor card, including the exact missing witness,
known CODE identities and the observation that would change the decision.
Use one view of those receipts instead of another authoritative ownership ledger.

## Recommended sequence and tool decisions

1. Review new targets with independent callers, full return paths, ABI and only
   supported obligations. Fresh discovery has 2,263 hypotheses, including 1,182
   prologue-only hints. The reserved `overlay-3:2344:237e` lead is still only a
   prologue hypothesis with no discovered callers; its branch paths and DS:5c19
   use need review before a worker card or target publication.
2. Run a small controlled compiler-context investigation on one parked helper.
   Predict a specific register/operand/frame change before compiling; preserve a
   baseline and a negative contrast. Scope every finding to exact source, flags,
   profile and complete object. Use real declaration/reference leads and the
   existing budget/hash journals, not another blind optimizer matrix.
3. Build a research provider frontier from the existing discovery relocation
   rows and whole pinned objects: provider public, missing frame/ABI witness,
   dependent candidates, supported/unsupported fixup shapes, secondary storage,
   and outside-witness locations. Review every raw call/pointer hint as original
   instructions. Select one closed, simple root case for the first far-call proof;
   keep ordered MZ correspondence and every field equation explicit.
4. Add a small JSON-driven codegen probe command only when a rule needs regular
   reproduction. Existing `compile_c`, OMF inspection and private scratch were
   sufficient for this audit. A useful command would require worker-local output,
   positive/negative controls, complete extents and raw declarations/fixups, and
   would never promote. Provider-frontier tooling is useful after one reviewed
   exemplar establishes its required fields.

No new tool installation is required for these steps. Do not transplant SimAnt's
`autosearch.py`: it assumes whole-module peer verification, research caches and
branch-displacement-insensitive diagnostic ranking. Its bounded rule catalogue
is a useful design pattern, but cannot replace pop2's full-extent/binding gate.
Likewise, differential emulation and source mutation controls would help later
ABI/behavior research; finite behavior agreement cannot close CODE_EXACT, RTLink
placement, provider identity or MZ relocation debt.
