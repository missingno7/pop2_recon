# Sibling reconstruction workflow findings

This note records concrete patterns from `D:\Prog\stunts_recon` (Stunts) and
`D:\Prog\empires_reconstruction` (Empires) that can inform Prince of Persia 2. The
sibling trees were inspected read-only. Their historical evidence and local
toolchains remain separate; reuse the workflow ideas and explicit proof
boundaries rather than copying project-specific assumptions.

## Stunts: evidence-led matching contributions

Stunts has a useful end-to-end split between immutable facts, scratch research,
and canonical ownership. `layout/oracle.lock.json` locks the source assets,
decoded/unpacked and packed images, image hashes, headers, and relocation data;
`tools/oracle.py` verifies/materializes the derived oracle without regenerating
the lock. `layout/manifest.json` is the ownership authority; `recipes/*.json`
carry per-contribution declarations and binding policy; `evidence/functions.json`,
symbol registries, reviewed overlays, and `evidence/` provide independent
anchors. Build output and worker reports are derived evidence, never ownership.
See `AGENTS.md`, `docs/acceptance.md`, and `docs/freeze.md` for invariants and
scope limits.

The normal investigation loop is deliberately light: `python tools/context.py
FUNCTION` prints oracle extent/hash, evidence quality, active recipe and recent
search observations; candidate C or MASM lives under an isolated
`build/workers/NAME/`; `python tools/search.py ... --function FUNCTION` freezes
the source/environment and reports compiler output and byte diagnostics. Search
is evidence gathering, not acceptance: unbound similarity cannot prove bindings,
object ownership, or translation-unit boundaries. `python tools/promote.py
FUNCTION candidate.c --verify-only` performs strict staged proof without
publication; promotion reruns fresh proofs, stages the ownership/recipe/source
change as a serialized recoverable transaction, and rebuilds the hybrid image.
Use `--batch` for dependent candidates that must pass singly and as one union.
Full `python tools/validate.py` is the tooling/acceptance boundary; `--image` is
a separately labelled diagnostic real-link check, not the canonical gate.

OMF acceptance is intentionally fail-closed. `tools/object_probe.py` preserves
complete SEGDEF declarations (including zero-length segments), publics,
externals/local scopes, groups, initialized payload, every supported FIXUPP,
and ordered relocation obligations. `tools/omf.py` refuses unknown/32-bit
records rather than silently skipping them. `tools/binder.py` supports a finite
set of tested binding modes; recipes state the exact declarations, expected
fixups, symbols, allowed addends and secondary segment extents. Original MZ
relocation words must be generated by candidate FIXUPPs, so an absolute literal
that happens to reproduce an operand is rejected. Relocations are checked in
exact order, not as an unordered set. A recipe may not trim a segment or ignore
unsupported OMF/storage declarations. `docs/acceptance.md` documents secondary
DGROUP and BSS rules, and when a real LINK run is required to prove placement.

Raw ownership is explicit debt. `tools/histbuild.py` freshly compiles accepted
recipes, assembles ASM, links named `Dnnn.OBJ` raw ranges and reports initialized
raw ranges, per-object BSS, pinned runtime, LINK fill, and raw-debt object
inventory separately. It is a reconstruction/link-order diagnostic; the README
explicitly distinguishes its current library-order residual from
`validate.py --image`'s oracle-derived exact comparison. Do not present a
hybrid exact result as complete source recovery, or conflate initialized raw,
BSS placeholders, runtime-library bytes, and link fill.

## Empires: grouped translation units and bounded runtime cards

Empires likewise separates oracle and production plan: `layout/production-plan.json`
defines ordered final modules and data/BSS inputs, while `layout/manifest.json`
and `recipes/modules/*.json` track ownership and grouped C/ASM contributions.
Its acceptance target is the pinned complete EXE SHA plus all 106 MZ relocations
in exact order from a single TLINK invocation. The README and
`docs/current/status.json` currently report that acceptance as current; only
`docs/current/` is authoritative status. `tools/build_exe.py verify` is the
uncached acceptance command. `--research` enables object caching and is never
acceptance; `--no-verify` omits the local fixture comparison but still enforces
the pinned full hash and relocation proof.

Translation-unit membership is treated as a binary fact to test, not inferred
from readable source organization. `docs/current/tu-structure.md` lists probe-
proven groups and distinguishing compiler clues: inline `asm` triggers TC2's
`-B` restart through TASM; functions that require `-B` but have no inline asm
must share a TU with one that does; SI/DI save order and frame contents expose
hand-written code; word-alignment pads identify TASM module boundaries;
descending native-C FIXUPP order constrains whether relocation-bearing neighbors
can share a unit; and a shared `_DATA` segment requires contiguous original data
components. `tools/probe_tu.py FIRST LAST` tests a contiguous candidate group,
`tools/tu_recipe.py` records a proven grouping, `tools/merge_module.py` applies
it, and `tools/audit_tu_flags.py --strict` finds unexplained flags. A matching
function in isolation does not establish the original TU.

The runtime block has a distinct bounded worker loop. `tools/reconstruction_factory.py
refresh` derives cards from the locked 6,571-byte runtime, CFG and evidence;
`next` selects the highest-priority CHEAP card. The worker edits only the card's
source-line interval in `asm/RUNTIME_BLOCK.ASM`, follows the TASM rules, and
runs the card's `verification_command`/`python tools/check_candidate.py ID`.
FAST reassembles the whole runtime and checks all bytes, public offsets, ordered
fixups, edit scope, and a strict reduction in unresolved bytes. Successful FAST
must be followed by `--promote`, which reruns FAST and performs full uncached
one-link acceptance. For a repeated or architectural blocker, `--block` archives
the isolated attempt, restores the accepted source snapshot, records the exact
blocked range, and refreshes cards; it refuses restoration if edits escaped the
card. See `docs/current/grinder-instructions.md` and
`docs/current/supervisor-instructions.md`. This bounded queue is specific to
the single runtime source; it should not be generalized into a quota or global
eligibility gate for ordinary source investigations.

The current Empires production builder consumes the complete module plan,
compiles final modules, emits initialized DATA and partitioned BSS, then runs
TLINK once. `tools/production_plan.py` derives that plan; `tools/build_production.py`
is the authoritative builder. Earlier probes and the runtime factory are
research/evidence tools and do not feed cached objects into acceptance.
`docs/current/workflow-audit.md` explicitly describes this as a production-line
improvement over staged linking. `docs/current/closure-frontier.md` separates
recovered C, irreducible inline ASM, genuine ASM and remaining evidence, rather
than treating all non-C bytes alike.

## Transferable checks for Prince of Persia 2

- Keep a hash-locked original oracle independent of candidate output; distinguish
  original evidence, hypotheses, tool limits and acceptance rules.
- Give every byte/segment an explicit owner or unresolved classification, and
  report source, assembly, pinned runtime, raw bytes and linker-generated fill
  independently.
- Let search compile exploratory candidates without granting ownership. Strict
  acceptance should consume frozen source, exact recipes, full object structure,
  independent symbol/binding evidence, and a freshly rebuilt complete image.
- Preserve complete declarations, all supported fixups, and exact relocation
  order. Fail closed on unsupported object records and storage semantics.
- Test likely TU/module groupings with the actual pinned compiler and linker;
  use emitted code, relocation sequence, alignment, and data placement as
  discriminating evidence.
- Use bounded worker cards only where source structure admits safe isolated
  edits. Make successful local checks a prerequisite to a fresh complete build,
  and make failure recovery preserve the accepted baseline.
- Keep a diagnostic reconstruction/link hypothesis distinct from byte-exact
  canonical acceptance, and state what the exact result proves and leaves open.
